## 跑到哪一步

```
$ python -m emu.run --chip mt6853 --max-ins 3000000

=== mt6853：从入口 0x28 开始 ===
=== 结束 ===
结果：指令数用尽
PC=0x0000556C  CPSR=0x400001F3  Thumb  模式=19
SP=0x00102708  LR=0x0000E04F  R0=0x00000000

串口 304 字节
timer 走了 104009
MMIO 读 19 个地址 / 写 14 个地址
```

**判据**：`LR = 0x0000E04F` 是 `sub_E244` 里 `bl 0x5A40` 的返回地址
⇒ 说明 BROM **已经进入 USB 下载态**（`sub_5A40`）。

**指令数下限约 300 万**。低于这个数会停在 `0x11AF4`（cache 维护循环），那是正常的。

## 启动路径

```
0x0000  复位向量：b 0x28
   ↓
0x0028  入口（ARM）
         · 清空 r0~ip
         · 0x84: bl 0x11CFC      ← 读 MPIDR，判断哪个核（tst r0,#0x700）
         · 0x8C: orr r0,#0xC0    ← 关 IRQ + FIQ
         · 0x98: ldr r2,=0x13238 → *(0x13238)=0x00102190
         · 0xA0: ldr r3,=0x13234 → *(0x13234)=0x00102750
         · 0xAC: sp = 0x102750 - 8 = 0x00102748
   ↓
0x01C4  外设初始化（bl 0x330 是空函数，bl 0x1AC 写 0x10008040/44）
   ↓
0x11D58 内存 / 数据段初始化
   ↓
0x7D48  检查 "GATJ"/"YALD" 标记 → 延时
   ↓
0xC0:   blx 0xDC04           ← 切 Thumb
   ↓
sub_DC04 → sub_E244          ← USB 下载态入口
   ├─ sub_E71C()  → UART 下载（等 a0 0a 50 05）
   ├─ sub_3E6C(1) → USB  下载（等 a0 0a 50 05）
   └─ 都不成立 → sub_8530(); sub_E09C(); sub_DE28(); while(1)
   ↓
LABEL_14 → sub_F830          ← 命令循环
```

## 内存布局

| 区域 | 地址范围 | 说明 |
|---|---|---|
| BROM ROM | `0x00000000` ~ `0x00020000` | 128 KB，只读 |
| SRAM | `0x00100000` ~ `0x00140000` | 栈顶 `0x00102748` |
| Timer | `0x10008048` | 自由运行计数器 |
| UART | `0x11002000` 数据 / `+0x14` 状态 | bit0=RX ready，**bit5**=TX ready |
| USB 控制器 | `0x11201000` | `+0x80` 状态、`+0x84` 掩码、`+0x300`+16·n 是 EP FIFO |
| eFuse | `0x11C10000` | `+0x90` = `sbc_pubk_hash3` |

### ⚠️ 位号容易看错

```
读 UART 状态：lsls r0, r0, #31   ⇒ 判 bit0
写 UART 状态：lsls r1, r1, #26   ⇒ 判 bit5（不是 bit6！）
```

`0x3E6C` 的超时循环里也是同样的写法，容易判错。

## BROM 内部 SRAM 变量

| 地址 | 类型 | 含义 | 相关函数 |
|---|---|---|---|
| `0x00102884` | u8 | 启动模式（0=停机，1=正常启动） | `sub_E84C` / `sub_E852` |
| `0x001054D8` | u32 | USB RX 数据长度 | `sub_5B26` |
| `0x001054DC` | buf | USB RX 数据 | `sub_5B26` |
| `0x001027B8` | u32 | USB RX 读指针 | `sub_5B26` |
| `0x001027BC` | u32 | USB TX 完成标志（中断里置 1） | `sub_5E42` |
| `0x00103B60` | u32 | `"GATJ"` 标记（前级阶段写的） | `sub_7D48` |
| `0x00103B64` | u32 | `"YALD"` 标记 | `sub_7D48` |
| `0x00103B68` | u32 | 延时值 | `sub_7D48` |

### USB 收发在 BROM 侧的实现

```c
// 取一个字节（sub_5B26）
if (MEMORY[0x1054D8]) {                    // RX 长度
    v3 = MEMORY[0x1027B8]++;               // 读指针
    *a1 = *(u8*)(v3 + 0x1054DC);           // 数据
    if (MEMORY[0x1054D8] == v3 + 1) {      // 读完了
        MEMORY[0x1054D8] = 0;
        MEMORY[0x1027B8] = 0;
    }
}

// 发送完成（sub_5E42）
MEMORY[0x1027BC] = 1;
```

⇒ **只要往 `0x1054D8` / `0x1054DC` 写数据，就等于"USB 收到了"。**
这是模拟器注入数据的全部接口。

## 延时标定

`sub_294(ms)` 把毫秒换成 timer tick：

```
ticks = (ms × 260 + 999) / 1000 + ms × 6500
上限 660737 ms（超过返回 -1）
```

代入 `ms = 15` ⇒ `97,504` tick。

⇒ 反推出 timer 频率约 **6.5 MHz**。

`sub_1FC(t0, ticks)` 是等待函数，带回绕处理：

```c
now = sub_1F0();               // 读 0x10008048
if (t0 > now)  elapsed = now + ~t0;   // 回绕
else           elapsed = now - t0;
return (ticks > elapsed) ? 0 : 1;
```

## 下载启动命令

```
a0 0a 50 05        4 字节，逐字节比对
```

| 路径 | 魔数位置 | 函数 |
|---|---|---|
| UART | `dword_133DC`（`0x133DC`） | `sub_E71C` |
| USB | `dword_12218[8]`（`0x12238`） | `sub_3E6C` |

收齐 4 字节 ⇒ 返回 1 ⇒ `sub_E244` 走 `LABEL_14` ⇒ `sub_F830` 命令循环。

**这正是 mtkclient 的 `brom_handshake()` 发出的那 4 个字节。**

## 启动模式为什么是 1

`sub_E84C` 只做一件事：

```c
int sub_E84C() {
    ldr r0, =0x00102884
    ldrb r0, [r0]
    bx lr
}
```

`sub_E244` 里：

```c
if (sub_E71C()) { …; goto LABEL_14; }      // UART 下载
if (sub_3E6C(1, …)) { …; goto LABEL_14; }  // USB 下载
…
sub_8530(); sub_E09C(&v15); sub_DE28();
while (1);                                  // 停机
```

> **这个 1 不是 BROM 自己算的**，来自复位配置 / boot strap。
> 模拟里直接强制成 1，否则 BROM 会走 `System halt!` 分支。

**旁证**：没有存储设备时，BROM 的串口日志是

```
BP: 0800 0200 [0000]
EC: 0000 0000 [0000]
S7: 0000 0000 [0000]
CC: 0000 0000 [0000]
T0: 0000 0011 [000F]
System halt!
```

`BP` = Boot Partition，读到 0 ⇒ 没有可启动设备 ⇒ 停机。

## 命令分发表（`sub_F830`）

```c
void __noreturn sub_F830() {
    sub_F81C();                          // 清 244 字节缓冲 + sub_638A()
    while (1) {
        c = sub_E890();                  // 读一个字节
        if (c == 0xFF) { sub_E8A6(5,1); continue; }
        sub_E8A6(c, 1);                  // 回显
        switch (c) {
          case 0xDC (220): sub_F746
          case 0xE4 (228): sub_F59E
          case 0xE5 (229): sub_F5B0
          case 0xE6 (230): sub_F618
          case 0xE7 (231): sub_F40A      // SOC_ID
          case 0xE8 (232): sub_F1D0      // ★ SEND_AUTH
          case 0xFC (252): sub_F3B6      // hw_sw_ver
          case 0xFD (253): sub_F398      // hw_code
          …
        }
    }
}
```

> ⚠️ **`0xE8` 才是 SEND_AUTH**（调用 `sub_F1D0`），不是 `0xE2`。
> 这一点在 `sub_108D8` 里也有旁证：`sub_F1D0(1, …)` 与 `sub_68D4(1051136, 1)` 成对出现。

## SEND_AUTH 的验签链

```
sub_F1D0 (0xE8 handler)
   └─ sub_E9B8(0x100A40, len, 1)      // 读数据到 0x100A40
      └─ sub_68D4(0x100A40, 1)
         ├─ sub_FA38(file, 0)          // 找 type-0 块
         ├─ sub_FABE(block)            // 块头校验
         ├─ sub_FA38(file, 4)          // 找 type-4 块
         ├─ sub_FBBC(blk0, blk4)       // 一致性检查
         │    · *(u32*)(blk4+8)  == 0x4C534D53
         │    · *(u32*)(blk4+12) == 0x544D5043
         │    · 若 HIBYTE(*(u32*)blk4) != 2 ⇒ *(u16*)(blk4+4)==592 且 blk0[27]==2
         ├─ MEMORY[0x102B0C] = blk4    // ★ 门闩（【早于】验签）
         ├─ HIBYTE(*blk4)==2 ? sub_6712 : sub_643A
         │    └─ sub_643A 里若 *(u32*)(blk4+64) & 0x80 ⇒ 只查 eFuse bit17
         ├─ MEMORY[0x102B14] = *(u32*)(blk4+64)   // ★ SLA 状态字
         └─ sub_90DE(0x105748, 0x105758, desc, 0)
              ├─ case 2 → sub_895C → sub_871E → sub_B32C
              │    · 签名最后一字节必须 0xBC
              │    · XOR 掩码（sub_B28C，种子 = sig[223:255]）
              │    · PKCS#1 v1.5 结构检查
              │    · 32 字节哈希比对
              └─ case 5 → sub_8AF6 → sub_8A1A → sub_B32C
```

**失败时**（`LABEL_32`）只清：

```
0x103B4C = 0;  0x103B50 = 0;
0x102B28 &= ~2u;   0x102AC0 起 44 字节清零
```

⇒ **`0x102B0C` / `0x102B14` 不回滚**，这是唯一的时序缺陷。
`sub_613E()` = `if (sub_611A() << 31) v0 = 0;`，而 `sub_611A()` = `0x102B0C ? 0x102B14 : 0`。

## 用调试器定位到的两件事

以下两条**无法从静态反编译直接看出**，是用 `emu/debug.py` 的内存断点抓到的。

### ① 启动模式是被 BROM 自己清零的

```python
dbg.watch(0x00102884, "w")
dbg.run(3_000_000)
# → 停止：内存写 0x102884 = 0x0（PC=0x11D98）
```

**⇒ `0x11D98` 是唯一写 `0x102884` 的地方**（在 `sub_11D58` 里，就是入口 `0xB8` 调的那个"内存初始化"）。
**⇒ 之后没有任何代码把它设回 1。**

**结论**：真机上那个 1 **不是 BROM 算出来的**，是复位配置/启动引脚在 BROM 运行之前就写好的。
模拟里必须强制成 1，否则 BROM 走 `System halt!`。

> 这条如果只读反编译会看不出来 —— `sub_E852` 是个"设置函数"，
> 但没有任何调用者给它传 1。**断点一挂就知道它是被清零而不是被设置。**

### ② 下载态是个"跳转到轮询"的紧循环

```python
dbg.bp(0x5A40)
dbg.run(8_000_000)
# → 停止：断点 0x5A40
#   指令计数 2,199,604
#   R2=0x11002000   R12=0x0D0A0D0A   LR=0x0000E04F
```

`0x5A40` 的第一条指令：

```
00005A40  b.w  #0x5516          ← 无条件跳到 USB 轮询
```

**⇒ 循环结构：**

```
0x5A40  b.w 0x5516
          ↓
0x5516  读 0x11201000 / 0x11201080 / 0x11201084
        无事件 ⇒ JUMPOUT(0x50E0)
          ↓
0x50E0  （sub_4FD4 的尾部）
          ↓
        返回 0x5A40，再来一次
```

**⇒ 所以卡住的原因很明确：事件寄存器恒为 0，永远没有事件。**

**要让它继续，需要给 `0x11201080`（事件）和 `0x11201084`（掩码）喂真实值。**

### 附：`LR=0xE04F` 是"进了下载态"的铁证

`0xE04F` 是 `sub_E244` 里 `bl 0x5A40` 的返回地址。看到它 ⇒ 已经过了两个开关
（`sub_E71C` UART / `sub_3E6C` USB），进到了下载主循环。

# 启动流程全景（实测版）

> 这一节是**跑通之后反推**的完整路径。箭头 => 表示"实测确认"，
> 没标的是反编译推断。地址都是文件偏移 = 运行时地址（BROM 基址 0）。

## 一、复位 → 主循环（ARM 段）

```
0x0000  b #0x28                        复位向量
         其余异常向量全是 `b 自己`（死循环）
0x0020  bb bb bb bb                    标记
0x0024  00 c9 53 0c                    某常量
0x0028  mov r0..#0xC 清 r0~ip
0x005C  mov sp, ip                     sp = 0
0x0084  bl 0x11CFC                     => 读 MPIDR（c0,c0,5），tst r0,#0x700
                                          实测 R0=0x80000000 ⇒ 不跳转 ⇒ 立即返回
0x0088  mrs / orr #0xC0 / msr          => 关 IRQ + FIQ
0x0098  ldr r2,=0x13238 → *(0x13238)=0x00102190
0x00A0  ldr r3,=0x13234 → *(0x13234)=0x00102750
0x00AC  sp = 0x102750 - 8              => SP = 0x00102748
0x00B4  bl 0x1C4                       外设初始化
0x00B8  bl 0x11D58                     数据段初始化（见下）
0x00BC  bl 0x7D48                      "GATJ"/"YALD" 标记 + 延时
0x00C0  blx 0xDC04                     => 切 Thumb，主入口
```

## 二、数据段初始化（`sub_11D58`）

只有两条：

```
sub_11D90(0x134DC, 0x102750, 0x1028B1)    ROM → SRAM，353 字节
sub_11DA4(0x1029F4, 0x102DC0)             清零 SRAM
```

`sub_11D90` 是 `while(dst<end) *dst++ = *src++;`（`0x11D90~0x11DA0`）。
`sub_11DA4` 是 `while(p<end) *p++ = 0;`。

**⇒ 启动模式 `0x102884` 就是这一步被写成 0 的**（源 = ROM `0x13610` = 0x00）。

## 三、`sub_7D48`：标记 + 延时

```
0x7D4C  ldr r0, =0x00103B60
0x7D50  ldr r2, =0x4A544147      "GATJ"（小端字节 47 41 54 4A）
0x7D54  ldr r1, [r0] ; cmp r1,r2 ; bne 0x7D94
0x7D60  ldr r1, [r0,#4] ; ldr r2,=0x444C4159   "YALD"
0x7D6C  bne 0x7D94
0x7D70  ldr r0, [r0,#8]          匹配时读第三个字当延时
0x7D94  mov r0,#0xF              不匹配时的默认值
0x7D98  bl 0x294                 毫秒 → tick
0x7DA8  bl 0x1FC                 等待
```

**⇒ `0x103B60` 的两个魔数是**前级阶段**写的；我们模拟时是 0 ⇒ 走默认 `delay(15ms)`。

## 四、`sub_DC04` → `sub_E244`（USB 下载态入口）

```
sub_DC04            （Thumb，__noreturn）
   └─ sub_E244      （__noreturn）
```

`sub_E244` 的实际执行顺序（**实测单步**）：

```
0xE244  push {r3, lr}
0xE246  bl 0x10EFA        => 读 eFuse 0x11C10120 bit11
0xE24A  cbnz r0, 0xE250   => bit11 = 0 ⇒ 不跳
0xE24C  bl 0xC06A         => 0x100070A4 |= 0x40000000
0xE250  bl 0x8530         => 读 eFuse 0x11C10130 bit12
0xE254  cmp r0, #1
0xE256  bne 0xE27A        => 那位是 0 ⇒ 跳（0xE258~0xE278 是 16 个 nop，死代码）
0xE27A  bl 0xE0FA         ★ 大初始化（330 字节）
0xE27E  movs r1,#0 / r0,#9 / bl 0xDB6
0xE286  bl 0x10B40
0xE296  bl 0xEA80         ★ USB 初始化，返回 v2
0xE29A  cbnz r0, 0xE2E0   => v2 != 0 ⇒ 跳过下载检查
        然后：sub_8530() / sub_E09C() / sub_DE28() / while(1)
```

## 五、`sub_E0FA`：开机自检（3 条停机路径都在这）

```c
sub_E0FA() {
    sub_DB6(0x33, 0);
    nullsub_8();
    sub_E67A("\n\r");              // 串口换行
    v4 = sub_E6E4(0);              // 清 0x102878 / 0x10287C
    sub_10D88(v4);
    v5 = sub_E63E(&v20);           // ★ 读"启动源"
    MEMORY[0x102874] = v5;
    if (v5 == 255 || v5 == 4) {
        sub_E5C4(4117, v20);
        if (MEMORY[0x102874] == 4)                     sub_DFB4(1);  // 停机①
        if (!sub_8462() && MEMORY[0x102874] == 255)     sub_DFB4(1);  // 停机②
    }
    …
    v18 = sub_DB02();
    if (v18 >= 0xFF) {
        sub_E5C4(v18, MEMORY[0x10287C]);
        if (!sub_8574())                                sub_DFB4(1);  // 停机③
    }
    return sub_DFE(0x33, …);
}
```

### `v5` 从哪来 —— `sub_E63E` → `sub_10FC8`

```c
sub_10FC8(int *a1) {
    v3 = MEMORY[0x1000A000] & 0xF;      // ★★★ 启动模式选择器
    *a1 = v3;
    switch (v3) { case 1: return 1; case 2: return 2;
                  case 3: return 3; case 7: return 4; }
    return 255;                          // 其它值
}
```

**⇒ `0x1000A000 & 0xF` 就是"启动源"：**

| 值 | 返回 | 结果 |
|---|---|---|
| 1 / 2 / 3 | 1/2/3 | 继续 |
| 7 | 4 | **停机①** |
| 其它（含 0） | 255 | **停机②**（且 `sub_8462()` = eFuse bit8 = 0） |

**⇒ 模拟里必须给 `0x1000A000` 一个 1/2/3，否则 BROM 一进 `sub_E0FA` 就停。**

## 六、`sub_EA80`：USB 检测

```c
int sub_EA80() {
    v2 = 0;
    if (sub_844E())                      { v0 = 0x8000; v2 = 1; }  // eFuse 0x11C10060 bit8
    v3 = sub_10BD8(8);
    if (v3 && *(u32*)(v3+44) == 0xC97E6A33) { v0 |= 0x4000; v2 = 1; }
    v4 = sub_10BD8(7);
    if (v4 && *(u8*)(v4+83) == 'R') v0 |= 1;
    if (v4 && *(u8*)(v4+84) == 'U') v0 |= 2;
    if (sub_EB10() == 1) v1 = 2;
    MEMORY[0x102898] |= (u16)v0 | (u16)v1;
    …
    return v2;                            // ★ 1 = 检测到特殊模式
}
```

`sub_10BD8(n)` 从 `MEMORY[0x106B64]`（描述符表）取第 n 项；
描述符表要满足 `+13 >= 4` 且 `+14 < 0xFF`。

**⇒ `sub_E244` 里是 `if (!sub_EA80())` ⇒ 想要继续，必须让它返回 **0**。**

## 七、`sub_DFB4`：兜底停机循环（`__noreturn`）

```
0xE040  bl 0xE84C          => 读 *(u8*)0x102884（启动模式）
0xE044  cmp r0, #1
0xE046  beq 0xE04A
0xE048  b 0xE048           ← 不是 1 就死在这
0xE04A  bl 0x5A40          ← 下载轮询循环
0xE04E  b 0xE04A
```

`0x5A40` = `b.w 0x5516`（同一条）。
`0x5516` 轮询 USB 事件寄存器后尾跳到 `0x4D6C`（那是 `pop.w {…,pc}` = 返回）。

**⇒ `sub_DFB4` 有 8 个调用者：`sub_E09C` / `sub_E0FA`×3 / `sub_EF30` / `sub_EFE0` / `sub_F0F4` / `sub_F2C0`。**

## 八、命令循环（`sub_F830`）—— 还没跑到

```
sub_E244 的 LABEL_14:
    v14 = sub_8530();
    sub_F830(v14);          ★ 命令循环（0xE8 = SEND_AUTH）
    while (1);
```

`sub_F830` 开头会 `sub_F81C()`（清 244 字节 + `sub_638A()`），
`sub_638A` 负责安装 USB 回调（`0x1029C8` 等）。

# 模拟时必须补的"非外设"东西

这些不是外设寄存器，但 Unicorn 不模拟，不给就会死循环或飞：

| 地址 / 机制 | 作用 | 不给的后果 |
|---|---|---|
| `0x1000A000 & 0xF` | **启动源选择器** | 返回 255 ⇒ `sub_E0FA` 停机 |
| `0x10008048` | 自由运行 timer | 延时函数死循环 |
| `0x11002000`/`+0x14` | UART 数据/状态（bit0/bit5） | 发不出字节，死循环 |
| `0x10210ABC` bit0 | 外设就绪 | `sub_C7FE` 死等 |
| `0x1029C8` 回调 | USB EP0 RX 处理 | 为 0 时上报事件 ⇒ **PC 飞 0** |
| **CP15 `c15,c3,#5/#7`** | cache size 选择 + 读回 | **`sub_117BC` 无限循环** |
| `0x102884` | 启动模式（1=继续） | `sub_DFB4` 死循环 |

## 关于 CP15 那个坑（值得单独记）

```asm
11BC  push {r1,r2}
11C0  mrc p15,0,r1,c15,c3,#5     读 cache size selection
11C4  bic r1,r1,#0xf0
11C8  and r0,r0,#0xf
11CC  orr r1,r1,r0,lsl #4
11D0  mcr p15,0,r1,c15,c3,#5     写
11D4  mrc p15,0,r1,c15,c3,#7     读回外层
11D8  mov r2,#0xf
11DC  and r2,r2,r1,lsr #4
11E0  cmp r2,r0
11E4  bne 0x11D4                 ★ 读回不符就永远循环
```

**Unicorn 完全不实现 CP15** ⇒ 读回恒 0 ⇒ 死循环。
修法：在 `0x11E0`（`cmp`）之前把 `r2 := r0`，让循环立刻结束。

# 调试技巧（这一轮踩出来的）

**① 断点自锁**
`emu_start(pc, count=1)` 在 PC 正好停在断点上时，每次都被 `emu_stop` 掐断。
⇒ `step()` 必须先**临时清空断点表**。

**② Thumb 模式必须带在 PC 里**
Unicorn 用 PC 的 bit0 选 ARM/Thumb。`emu_start(pc)` 会让 Thumb 代码按 ARM 解。
⇒ 继续执行时必须 `pc | (CPSR.T ? 1 : 0)`。

**③ 断点链式跟踪**
想看"它在哪一步转弯"，就打一串断点，每次命中后 `step(1)` + 移除已命中项，
再 `run()` 到下一个。比单步快得多。

**④ watchpoint 找写入者**
```python
dbg.watch(0x00102884, "w")
dbg.run(3_000_000)
# → 内存写 0x102884 = 0x0（PC=0x11D98）
```
**⇒ 直接给出写入指令的地址，再反查是哪个函数、什么语义。**
