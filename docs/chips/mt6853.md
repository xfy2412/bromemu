## 跑到哪一步

```
$ python -m emu.run --chip mt6853 --max-ins 3000000

=== mt6853：从入口 0x28 开始 ===
=== 结束 ===
结果：指令数用尽
PC=0x0000556C  CPSR=0x400001F3  Thumb  模式=19
SP=0x00102708  LR=0x0000E04F  R0=0x00000000

串口 304 字节
timer 走了 104009
MMIO 读 19 个地址 / 写 14 个地址
```

**判据**：`LR = 0x0000E04F` 是 `sub_E244` 里 `bl 0x5A40` 的返回地址
⇒ 说明 BROM **已经进入 USB 下载态**（`sub_5A40`）。

**指令数下限约 300 万**。低于这个数会停在 `0x11AF4`（cache 维护循环），那是正常的。

## 启动路径

```
0x0000  复位向量：b 0x28
   ↓
0x0028  入口（ARM）
         · 清空 r0~ip
         · 0x84: bl 0x11CFC      ← 读 MPIDR，判断哪个核（tst r0,#0x700）
         · 0x8C: orr r0,#0xC0    ← 关 IRQ + FIQ
         · 0x98: ldr r2,=0x13238 → *(0x13238)=0x00102190
         · 0xA0: ldr r3,=0x13234 → *(0x13234)=0x00102750
         · 0xAC: sp = 0x102750 - 8 = 0x00102748
   ↓
0x01C4  外设初始化（bl 0x330 是空函数，bl 0x1AC 写 0x10008040/44）
   ↓
0x11D58 内存 / 数据段初始化
   ↓
0x7D48  检查 "GATJ"/"YALD" 标记 → 延时
   ↓
0xC0:   blx 0xDC04           ← 切 Thumb
   ↓
sub_DC04 → sub_E244          ← USB 下载态入口
   ├─ sub_E71C()  → UART 下载（等 a0 0a 50 05）
   ├─ sub_3E6C(1) → USB  下载（等 a0 0a 50 05）
   └─ 都不成立 → sub_8530(); sub_E09C(); sub_DE28(); while(1)
   ↓
LABEL_14 → sub_F830          ← 命令循环
```

## 内存布局

| 区域 | 地址范围 | 说明 |
|---|---|---|
| BROM ROM | `0x00000000` ~ `0x00020000` | 128 KB，只读 |
| SRAM | `0x00100000` ~ `0x00140000` | 栈顶 `0x00102748` |
| Timer | `0x10008048` | 自由运行计数器 |
| UART | `0x11002000` 数据 / `+0x14` 状态 | bit0=RX ready，**bit5**=TX ready |
| USB 控制器 | `0x11201000` | `+0x80` 状态、`+0x84` 掩码、`+0x300`+16·n 是 EP FIFO |
| eFuse | `0x11C10000` | `+0x90` = `sbc_pubk_hash3` |

### ⚠️ 位号容易看错

```
读 UART 状态：lsls r0, r0, #31   ⇒ 判 bit0
写 UART 状态：lsls r1, r1, #26   ⇒ 判 bit5（不是 bit6！）
```

`0x3E6C` 的超时循环里也是同样的写法，容易判错。

## BROM 内部 SRAM 变量

| 地址 | 类型 | 含义 | 相关函数 |
|---|---|---|---|
| `0x00102884` | u8 | 启动模式（0=停机，1=正常启动） | `sub_E84C` / `sub_E852` |
| `0x001054D8` | u32 | USB RX 数据长度 | `sub_5B26` |
| `0x001054DC` | buf | USB RX 数据 | `sub_5B26` |
| `0x001027B8` | u32 | USB RX 读指针 | `sub_5B26` |
| `0x001027BC` | u32 | USB TX 完成标志（中断里置 1） | `sub_5E42` |
| `0x00103B60` | u32 | `"GATJ"` 标记（前级阶段写的） | `sub_7D48` |
| `0x00103B64` | u32 | `"YALD"` 标记 | `sub_7D48` |
| `0x00103B68` | u32 | 延时值 | `sub_7D48` |

### USB 收发在 BROM 侧的实现

```c
// 取一个字节（sub_5B26）
if (MEMORY[0x1054D8]) {                    // RX 长度
    v3 = MEMORY[0x1027B8]++;               // 读指针
    *a1 = *(u8*)(v3 + 0x1054DC);           // 数据
    if (MEMORY[0x1054D8] == v3 + 1) {      // 读完了
        MEMORY[0x1054D8] = 0;
        MEMORY[0x1027B8] = 0;
    }
}

// 发送完成（sub_5E42）
MEMORY[0x1027BC] = 1;
```

⇒ **只要往 `0x1054D8` / `0x1054DC` 写数据，就等于"USB 收到了"。**
这是模拟器注入数据的全部接口。

## 延时标定

`sub_294(ms)` 把毫秒换成 timer tick：

```
ticks = (ms × 260 + 999) / 1000 + ms × 6500
上限 660737 ms（超过返回 -1）
```

代入 `ms = 15` ⇒ `97,504` tick。

⇒ 反推出 timer 频率约 **6.5 MHz**。

`sub_1FC(t0, ticks)` 是等待函数，带回绕处理：

```c
now = sub_1F0();               // 读 0x10008048
if (t0 > now)  elapsed = now + ~t0;   // 回绕
else           elapsed = now - t0;
return (ticks > elapsed) ? 0 : 1;
```

## 下载启动命令

```
a0 0a 50 05        4 字节，逐字节比对
```

| 路径 | 魔数位置 | 函数 |
|---|---|---|
| UART | `dword_133DC`（`0x133DC`） | `sub_E71C` |
| USB | `dword_12218[8]`（`0x12238`） | `sub_3E6C` |

收齐 4 字节 ⇒ 返回 1 ⇒ `sub_E244` 走 `LABEL_14` ⇒ `sub_F830` 命令循环。

**这正是 mtkclient 的 `brom_handshake()` 发出的那 4 个字节。**

## 启动模式为什么是 1

`sub_E84C` 只做一件事：

```c
int sub_E84C() {
    ldr r0, =0x00102884
    ldrb r0, [r0]
    bx lr
}
```

`sub_E244` 里：

```c
if (sub_E71C()) { …; goto LABEL_14; }      // UART 下载
if (sub_3E6C(1, …)) { …; goto LABEL_14; }  // USB 下载
…
sub_8530(); sub_E09C(&v15); sub_DE28();
while (1);                                  // 停机
```

> **这个 1 不是 BROM 自己算的**，来自复位配置 / boot strap。
> 模拟里直接强制成 1，否则 BROM 会走 `System halt!` 分支。

**旁证**：没有存储设备时，BROM 的串口日志是

```
BP: 0800 0200 [0000]
EC: 0000 0000 [0000]
S7: 0000 0000 [0000]
CC: 0000 0000 [0000]
T0: 0000 0011 [000F]
System halt!
```

`BP` = Boot Partition，读到 0 ⇒ 没有可启动设备 ⇒ 停机。

## 命令分发表（`sub_F830`）

```c
void __noreturn sub_F830() {
    sub_F81C();                          // 清 244 字节缓冲 + sub_638A()
    while (1) {
        c = sub_E890();                  // 读一个字节
        if (c == 0xFF) { sub_E8A6(5,1); continue; }
        sub_E8A6(c, 1);                  // 回显
        switch (c) {
          case 0xDC (220): sub_F746
          case 0xE4 (228): sub_F59E
          case 0xE5 (229): sub_F5B0
          case 0xE6 (230): sub_F618
          case 0xE7 (231): sub_F40A      // SOC_ID
          case 0xE8 (232): sub_F1D0      // ★ SEND_AUTH
          case 0xFC (252): sub_F3B6      // hw_sw_ver
          case 0xFD (253): sub_F398      // hw_code
          …
        }
    }
}
```

> ⚠️ **`0xE8` 才是 SEND_AUTH**（调用 `sub_F1D0`），不是 `0xE2`。
> 这一点在 `sub_108D8` 里也有旁证：`sub_F1D0(1, …)` 与 `sub_68D4(1051136, 1)` 成对出现。

## SEND_AUTH 的验签链

```
sub_F1D0 (0xE8 handler)
   └─ sub_E9B8(0x100A40, len, 1)      // 读数据到 0x100A40
      └─ sub_68D4(0x100A40, 1)
         ├─ sub_FA38(file, 0)          // 找 type-0 块
         ├─ sub_FABE(block)            // 块头校验
         ├─ sub_FA38(file, 4)          // 找 type-4 块
         ├─ sub_FBBC(blk0, blk4)       // 一致性检查
         │    · *(u32*)(blk4+8)  == 0x4C534D53
         │    · *(u32*)(blk4+12) == 0x544D5043
         │    · 若 HIBYTE(*(u32*)blk4) != 2 ⇒ *(u16*)(blk4+4)==592 且 blk0[27]==2
         ├─ MEMORY[0x102B0C] = blk4    // ★ 门闩（【早于】验签）
         ├─ HIBYTE(*blk4)==2 ? sub_6712 : sub_643A
         │    └─ sub_643A 里若 *(u32*)(blk4+64) & 0x80 ⇒ 只查 eFuse bit17
         ├─ MEMORY[0x102B14] = *(u32*)(blk4+64)   // ★ SLA 状态字
         └─ sub_90DE(0x105748, 0x105758, desc, 0)
              ├─ case 2 → sub_895C → sub_871E → sub_B32C
              │    · 签名最后一字节必须 0xBC
              │    · XOR 掩码（sub_B28C，种子 = sig[223:255]）
              │    · PKCS#1 v1.5 结构检查
              │    · 32 字节哈希比对
              └─ case 5 → sub_8AF6 → sub_8A1A → sub_B32C
```

**失败时**（`LABEL_32`）只清：

```
0x103B4C = 0;  0x103B50 = 0;
0x102B28 &= ~2u;   0x102AC0 起 44 字节清零
```

⇒ **`0x102B0C` / `0x102B14` 不回滚**，这是唯一的时序缺陷。
`sub_613E()` = `if (sub_611A() << 31) v0 = 0;`，而 `sub_611A()` = `0x102B0C ? 0x102B14 : 0`。
